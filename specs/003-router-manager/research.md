# Research: router-manager

Решения о сторонних компонентах и механизмах. «Проверено» — выполнено при подготовке дизайна на одноразовых прототипах
(Go 1.26.11, `golang:1.26.11-bookworm`, PostgreSQL 16-alpine, Redis 8.6.7-alpine с Sentinel, Keycloak 26.0.8, Grafana 11.2.0,
Loki 3.1.1, buf 1.47.2, Docker Desktop arm64); код прототипов в репозиторий не входит. «Предположение» — не проверялось:
задача с пометкой `(Rn)` проверяет его до зависящего кода; не подтвердилось — исполнитель останавливается, применяется
запасной вариант, правятся plan.md и ADR, повторяется `analyze`.

## Иллюстративные примеры исходной постановки

Схема задания и примеры теории — иллюстрации; ниже — что в них не так и что сделано иначе.

- Схема задания называет будущего администратора номером учебной части; в документах — «API-оркестратор». Ключи Keycloak
  нарисованы стрелкой от Keycloak, но запрос идёт от router-manager (он сам забирает JWKS). Проверка роутеров на схеме не
  показана — она выбрана здесь (R17, ADR-0023).
- Теория, рис. 1: Java-сервис и Go-сервис оба ходят SQL в одну PostgreSQL — нарушает «один владелец данных»; у router-manager
  своя база, другие сервисы читают статус только через его gRPC.
- Теория, Go-сервер gRPC: без дедлайнов, перехвата паник, health и `GracefulStop` по сигналу, `log.Fatal` при ошибке. Здесь
  все четыре есть (plan.md, «Ключевые решения»).
- Теория, Go HTTP/2-клиент: `Timeout` клиента 3 с и контекст 2 с — два противоречащих срока; `panic` вместо ошибки;
  `SetHTTP1(true)` + `SetHTTP2(true)` — это не «только HTTP/2». Здесь один срок — из контекста вызова.
- Теория: «Keycloak — не центр темы» — задание требует сервисный токен Keycloak; действует задание.
- Репозиторий видео (GolangLessons/sso): логирует тела запросов (`PayloadReceived`/`PayloadSent`) — пароли в логах;
  конфигурация из YAML и `CONFIG_PATH` (у нас только окружение); SQLite и свой мигратор (у нас pgx и db-migrator);
  HS256 с секретом приложения в той же базе (у нас RS256 Keycloak); `Prepare` без `Close` и без контекста; тайм-аут
  `grpc.timeout` из конфигурации нигде не применяется; неверный пароль → `InvalidArgument` (должно быть `Unauthenticated`);
  функциональные тесты требуют заранее запущенного сервиса (у нас Testcontainers). Взято: раскладка
  `cmd/` + `internal/`, интерфейсы по месту использования, `slog`, остановка по сигналу, тесты через сгенерированный клиент.
