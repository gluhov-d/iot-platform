# Specification Quality Checklist: failed-events

**Purpose**: проверка качества требований spec.md перед реализацией
**Created**: 2026-11-21
**Feature**: [spec.md](../spec.md)

**Review Ownership**: чек-лист проверяет качество требований; `[x]` — критерий проверен для spec.md, plan.md и tasks.md, а не «работа сделана».

## Content Quality

- [x] CHK001 Требования описывают поведение и проверку, а не классы; детали реализации — в plan.md, data-model.md, tasks.md
- [x] CHK002 Все обязательные разделы заполнены: Clarifications, User Scenarios, Requirements, Success Criteria, Assumptions, Критерии приёмки

## Requirement Completeness

- [x] CHK003 Нет маркеров `[NEEDS CLARIFICATION]`; вопросы раздела 7 задания (ключ объекта, поиск, нечитаемое сообщение, всплеск, копии) разобраны в Clarifications и ADR
- [x] CHK004 У каждого FR есть проверка «что вызвать — что получить»; каждый FR и SC покрыт задачей tasks.md (скрипт согласованности вне репозитория: 30 из 30)
- [x] CHK005 Критерии успеха измеримы (число объектов, версий, состояние группы, числа в manifest)
- [x] CHK006 Граничные случаи названы: повторная публикация сборщиком, ключ не UTF-8, нет `traceparent`, MinIO недоступен дольше `max.poll.interval.ms`, перезапуск над непустым бакетом
- [x] CHK007 Границы заданы: «Дополнительно» вынесено в необязательную фазу, каскад обработчиков не берётся с причиной
- [x] CHK008 Зависимости и допущения названы: одна нода MinIO, `pg_dump` не PITR, форк образа MinIO

## Feature Readiness

- [x] CHK009 Предположения о сторонних компонентах закрыты прототипом или имеют проверяющую задачу и запасной вариант (research.md, R1–R23)
- [x] CHK010 Необратимые действия (публикация avros 1.4.0, удаление DLT-тем на стенде владельца) — задачи **ЧЕЛОВЕК**
- [x] CHK011 Каждая задача tasks.md с кодом содержит путь файла; тест раньше кода; у фаз есть Checkpoint
- [x] CHK012 Имена переменных, метрик, кодов ошибок и классов тестов одинаковы в spec, plan, data-model и tasks (проверено чтением и скриптом согласованности вне репозитория)
- [x] CHK013 Расхождения с иллюстративными примерами исходной постановки перечислены в research.md и закрыты решениями

- Не проверено: скорость процессора при всплеске (R20), arm64 на macOS-хосте (R22), возврат смещений группы при restore и `flock` (R18), IT сборщика с процессором вторым контекстом (R23).
