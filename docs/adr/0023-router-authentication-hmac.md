# ADR-0023: Проверка вызывающих: сервисный токен и подпись роутера

**Статус**: предложено, 2026-11-28 (на проверке дизайна). Спецификация — [specs/003-router-manager](../../specs/003-router-manager/spec.md).

## Контекст

Методы администратора по заданию принимают только сервисный токен Keycloak, как device-service (ADR-0007). Способ проверки
роутеров — на выбор, роутеров миллионы. Клиент Keycloak на роутер, токен в базе или сертификат на роутер — каждый со своей ценой.

## Решение

- Администратор: RS256 по ключам realm (`keyfunc/v3`, кэш, обновление на неизвестный `kid` не чаще раза в минуту), `iss`, `exp`,
  аудитория `router-manager`, `client_id` есть и `sid` нет, роли клиента `router-manager`: `commands.write`, `commands.read`. Без
  ключей при старте сервис не стартует (иначе молча отвергает всё, research.md R15). Клиенты realm: `router-manager`,
  `router-manager-consumer`, `router-manager-reader`.
- Роутер: ключ `K_r = HMAC-SHA256(K_master, router_id)` записывается при производстве; запрос несёт `x-router-id`, `x-router-ts`,
  `x-router-nonce`, `x-router-key-id`, `x-router-sig` = HMAC от имени метода, `router_id`, времени, nonce и полей тела
  (`command_id`, `outcome`, SHA-256 от `message`; строка — data-model.md). Сервис выводит ключ сам: ни базы, ни Keycloak,
  0,7–0,8 мкс (R17). Окно ±60 с; ротация — два мастер-ключа по идентификатору.
- Одноразовость: верная подпись записывается `SET NX router:sig:v1:{routerId}:{sig}` на 120 с (вдвое больше окна); запись не
  удалась — повтор (R23). Redis недоступен — запрос принимается, `router_manager_replay_check_skipped_total` +1: доступность
  опросов важнее, чем защита от повтора на время сбоя Redis. Отказ — `UNAUTHENTICATED` без подробностей.

## Рассмотренные варианты

- mTLS с сертификатом роутера от CA платформы: сильнее (повтор невозможен, ключ не покидает роутер), но CA, выпуск и отзыв
  сертификатов, TLS в Compose и эмуляторе — отдельная инфраструктура; путь развития, если появится провижининг.
- Клиент Keycloak на роутер: миллионы клиентов и выдача токенов — Keycloak становится узким местом.
- Токен роутера в базе с кэшем в Redis: каждый промах кэша — запрос в базу на каждом опросе, хранение секретов миллионов роутеров.
- Подпись только метаданных (без тела и одноразовости): перехваченные за балансировщиком заголовки в окне ±60 с позволяли
  подменить итог `ReportResult` и повтором `PollCommand` забрать чужую команду (она уходила бы в TIMEOUT с оповещением).
- Отказ при недоступном Redis: защищает от повтора и во время сбоя, но останавливает опросы всех роутеров.

## Последствия

- Утечка мастер-ключа компрометирует все роутеры — ключ только в окружении сервиса (секрет), ротация через второй ключ.
- Каждый опрос пишет в Redis одну короткую запись (живёт 120 с): при частоте опросов N в секунду в Redis ~120·N ключей подписей.
- Пока Redis недоступен, повтор перехваченного запроса возможен; это видно по `router_manager_replay_check_skipped_total`.
- Внешний порт в продуктиве — TLS на балансировщике (на стенде — открытый HTTP/2 внутри сети Compose).
- Эмулятор знает мастер-ключ стенда, чтобы вывести ключи своих роутеров.
