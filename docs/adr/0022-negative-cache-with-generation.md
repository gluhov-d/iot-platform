# ADR-0022: Негативный кэш с поколением роутера

**Статус**: предложено, 2026-11-28 (на проверке дизайна). Спецификация — [specs/003-router-manager](../../specs/003-router-manager/spec.md).

## Контекст

Задание: факт «для роутера команды нет» кэшируется в Redis платформы, повторные опросы до базы не доходят; создание команды
сбрасывает запись; при интервале 10 с команда выдаётся не позже третьего опроса; при недоступном Redis — работа через базу.
Простое «удалить ключ после создания» проигрывает гонку: опрос прочитал базу до фиксации, а записал «нет команды» после удаления.

## Решение

- Ключи `router:cmd:none:v1:{routerId}` (срок `ROUTER_NEG_CACHE_TTL` = 15 с) и `router:cmd:gen:v1:{routerId}` (поколение).
- Опрос: запись есть — ответ без базы. Нет — запоминает поколение, идёт в базу; команды нет — Lua «записать, если поколение то же».
- Создание: фиксация в PostgreSQL → Lua «`INCR` поколения, продлить срок, удалить запись». Ответ администратору — после фиксации;
  ошибка Redis ответ не меняет (источник истины — база).
- Граница при сбое Redis в момент создания: запись живёт не дольше `ROUTER_REQUEST_TIMEOUT + ROUTER_NEG_CACHE_TTL` = 17 с после
  фиксации, третий опрос — не раньше 20 с. Сервис не стартует при `TTL + REQUEST_TIMEOUT ≥ 20 с`. Граница держится на том, что
  go-redis соблюдает срок вызова (R7) — это предположение, его проверяет T021; не подтвердится — срок ограничивают
  `ReadTimeout`/`WriteTimeout` клиента (≤ `ROUTER_REDIS_TIMEOUT`), и граница становится `REQUEST_TIMEOUT + REDIS_TIMEOUT + TTL`.
- Клиент — Sentinel (`platform-redis`), `ContextTimeoutEnabled` (срок вызова, предположение research.md R7), тайм-ауты 100 мс; ошибка Redis —
  путь через базу (R6: ~260 мс при приостановленном Redis).

Проверено на прототипе (research.md R5): детерминированная гонка не оставляет записи.

## Рассмотренные варианты

- Только короткий срок записи без поколения — гонка остаётся, гарантия держится лишь на сроке.
- Кэш положительных ответов (сама команда в Redis) — второй источник статуса, усложняет «выдать один раз».
- Pub/sub-сброс между экземплярами — не нужен: состояние только в Redis.

## Последствия

- Миллионы роутеров — до двух коротких ключей на роутер (плюс записи принятых подписей, ADR-0023); ключ поколения истекает через `ROUTER_GEN_TTL`.
- Негативный кэш можно выключить (`ROUTER_NEG_CACHE_ENABLED=false`) для замера нагрузки на базу без него.
