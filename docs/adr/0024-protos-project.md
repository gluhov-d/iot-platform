# ADR-0024: Проект protos и генерация Go-кода

**Статус**: предложено, 2026-11-28 (на проверке дизайна). Спецификация — [specs/003-router-manager](../../specs/003-router-manager/spec.md).

## Контекст

Задание: отдельный проект `protos` по образцу avros со всеми `.proto` платформы; сборка проверяет совместимость с предыдущей
версией и публикует версионированный артефакт в Nexus; Go-код сервиса и эмулятора генерируется из тех же файлов, ручных
транспортных структур нет; дальше артефакт подключит Java-оркестратор.

## Решение

- `protos/`: Gradle-проект, jar `com.github.gluhov.iotplatform:protos` с `proto/**` и `buf.yaml` (без сгенерированных классов —
  каждый язык генерирует своё), `maven-releases`, выпущенная версия не перезаписывается; первая — 1.0.0.
- Проверки: `buf lint` STANDARD без исключений (файл в `iotplatform/router/v1/`, сервисы `…Service`, значения enum с префиксом);
  `buf breaking` с правилами `WIRE_JSON` против `.proto` последнего релиза из Nexus. `FILE` не допускает удаление поля даже
  через `reserved`; `WIRE` пропускает переименование значения enum, ломающее JSON (research.md R14). `buf` — из образа
  `bufbuild/buf` 1.47.2 внутри образа сборки protos.
- Go: один модуль `services/router-manager` с программами `router-manager` и `router-emulator` и одним сгенерированным пакетом
  `internal/gen` — интеграционный тест подключает эмулятор как библиотеку, а две копии сгенерированного кода в одном бинарнике
  конфликтуют в реестре protobuf (предположение R20 по документации protobuf-go, проверяет T011). Код генерирует `buf generate` с локальными плагинами фиксированных версий из `.proto`
  версии `PROTOS_VERSION`, скачанной из Nexus; в Git не попадает.

## Рассмотренные варианты

- Сгенерированный Go-код в Git: проще локально, но расходится с правилом проекта «сгенерированное — при сборке».
- Генерация прямо из каталога `protos/`: версия контракта у сервиса не фиксируется (решение владельца — явная версия).
- Удалённые плагины buf.build: сборка зависит от внешнего сервиса.

## Последствия

- Изменение контракта сервису доступно только после публикации новой версии (шаг человека).
- Сборка образа router-manager требует Nexus, как сборка Java-сервисов.
